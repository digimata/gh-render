# ISS-0001 — Require a standalone ownership marker before treating files as managed

GitHub: [#1](https://github.com/digimata/gh-render/issues/1)

## Problem

`issues.IsManagedContent` searches for the ownership marker as an arbitrary byte substring before the first `# ` heading. It does not require the marker to occupy its own line.

An unmanaged file such as:

```markdown
This note mentions <!-- gh-render:managed --> in prose.

# Personal notes
```

is therefore classified as renderer-owned. If its filename matches `iss-\d{4,}\.md` and it is outside the active selection, normal rendering can delete it as stale.

## Relevant code

- `internal/issues/render.go`: `IsManagedContent`
- `internal/projection/writer.go`: stale-file inventory and removal

## Expected behavior

Ownership should require the exact marker on a standalone line in the generated preamble, before the first top-level heading. Embedded marker text must never grant ownership.

## Acceptance criteria

- Embedded marker text before a heading is rejected.
- Embedded marker text in frontmatter string values is rejected.
- The generated index marker at byte zero remains accepted.
- The generated issue marker after frontmatter remains accepted.
- A filesystem test proves that an unmanaged matching file containing embedded marker text is never removed.
