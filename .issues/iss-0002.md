# ISS-0002 — Reconcile unmanaged matching-file behavior with the issues specification

GitHub: [#2](https://github.com/digimata/gh-render/issues/2)

## Problem

The authoritative issues specification says:

> Unmanaged matching files cause the render to fail before any write.

The implementation instead ignores a nonexpected direct child whose filename matches `iss-\d{4,}\.md` but whose content is unmanaged. `TestBuildPlanIgnoresUnownedStrays` explicitly locks in that behavior.

Observed reproduction:

1. Place an unmanaged `iss-9999.md` in the output directory.
2. Render a repository whose selected projection does not include issue 9999.
3. `--dry-run` exits successfully and ignores the conflicting file.

This conflicts with `docs/objects/issues.md` §8. The detailed implementation plan says authoritative specifications win when they disagree.

## Relevant code

- `internal/projection/writer.go`: stale-child inventory
- `tests/projection/projection_test.go`: `TestBuildPlanIgnoresUnownedStrays`
- `docs/objects/issues.md`: §8 Stale-file behavior

## Acceptance criteria

- Decide and document whether an unmanaged renderer-pattern filename is a conflict or an ignored stray.
- Keep `docs/objects/issues.md`, the implementation plan, production behavior, and tests consistent.
- If the authoritative behavior remains unchanged, reject the complete plan before any mutation and identify the conflicting path.
