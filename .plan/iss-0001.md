# ISS-0001 — Require a Standalone Ownership Marker

## Context

The issues renderer deletes stale files only when their filename and content identify them as renderer-owned. The content predicate therefore sits on a destructive filesystem boundary.

## Problem statement

An unmanaged matching file can be classified as owned when it merely contains `<!-- gh-render:managed -->` inside prose or a frontmatter value before its first top-level heading.

## RCA

`issues.IsManagedContent` uses `bytes.Index` to find the marker as an unrestricted substring. It compares only the substring offset with the first heading offset, so the marker does not need to occupy the generated standalone marker line.

## Changes

1. Scan the pre-heading content line by line.
2. Grant ownership only when a complete line equals the exact marker.
3. Accept either LF or CRLF line delimiters without accepting surrounding whitespace or text.
4. Add predicate tests for embedded prose, frontmatter, whitespace, CRLF, and body-only occurrences.
5. Add a filesystem regression proving embedded marker text cannot cause stale deletion.

## Relevant files

- `internal/issues/render.go` — ownership predicate.
- `tests/issues/render_test.go` — ownership classification matrix.
- `tests/projection/writer_test.go` — destructive-boundary regression.

## Verification
